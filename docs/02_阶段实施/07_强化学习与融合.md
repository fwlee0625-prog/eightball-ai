# 阶段 M7：强化学习与融合

## 1. 本阶段目标
在可校准仿真环境里自我提升并与传统搜索融合。

## 2. 开始前必须具备
完成上一阶段的验收；参照总体路线与数据字典，核对输入是否真实可得；缺少授权真实数据时先使用人工合成测试数据。

## 3. 逐项执行顺序
- [ ] **步骤 8.1**：先把每杆或一局作为 Gymnasium 环境，明确 observation/action/奖励/终止。
- [ ] **步骤 8.2**：奖励处理合法进球、白球停位、犯规、完成清台和防守。
- [ ] **步骤 8.3**：先离散候选动作，后在验证后尝试连续动作 SAC。
- [ ] **步骤 8.4**：域随机化模拟桌差与人类误差。。

## 4. 应让 AI/Codex 实现的工作
实现 `reset`/`step` 及 `check_env`；训练基线策略；日志和固定种子实验；比较纯搜索、纯行为克隆、RL、融合策略的成功率/风险；策略只提出候选，再由规则和仿真筛查。

将任务拆成每次可运行的最小提交：先定义接口和假数据，再实现主流程，再补边界测试，最后做 UI 和性能。每次提交必须记录为什么这么做。

## 5. 需要自己掌握的原理
马尔可夫决策过程、reward hacking、SAC/PPO 选择、仿真到真实偏移、离线数据不能自动保证可泛化。

要求自己能回答：本步骤输入是什么、输出是什么、依赖的假设是什么、有哪些反例、怎么验证而不是凭感觉判断？

## 6. 验收与下一阶段入口
训练曲线与独立随机种子测试保留；多样化球桌参数上不明显崩溃；真实对照失败则不发布。

## 7. 常见跑偏与纠正
- 第三方库接口未知时先跑官方最小示例，不凭记忆写不存在的方法。
- 失败样例必须记录，不能只展示一条成功演示。
- 和职业水平有关的结论必须基于现实的独立数据验证。
- 复杂算法不必立即引入，先把最简单可评测的基线做出来。

## 每一步的统一完成标准（DoD）
1. 代码进入版本控制，类型检查、格式化及单元测试通过。
2. 使用固定样例运行并保存输入、输出、运行环境与耗时。
3. 至少编写一条正常、一条边界、一条异常测试。
4. README 中有运行命令、重现步骤、已知限制。
5. 未达到验收标准不得把任务标记为完成；记录失败原因、后续实验。

## 给 Codex 的统一任务模板
> 请先阅读 README、架构设计、数据字典和本阶段文档。仅实现本步骤，不新增微服务。先列出拟改文件与验收测试；实现后执行测试，并报告修改文件、命令、结果、风险和遗留事项。若 Pooltool 或其他第三方 API 与当前官方文档不一致，先验证版本并给出最小可运行示例，禁止猜测接口。

# 阶段 M6：模仿学习

## 1. 本阶段目标
把专家示范用于策略先验和候选生成，而非视为全部标准答案。

## 2. 开始前必须具备
完成上一阶段的验收；参照总体路线与数据字典，核对输入是否真实可得；缺少授权真实数据时先使用人工合成测试数据。

## 3. 逐项执行顺序
- [ ] **步骤 7.1**：制定球员口述标签（目标球、袋口、杆法、主观力度、目标白球区域）。
- [ ] **步骤 7.2**：抽检一致性。
- [ ] **步骤 7.3**：动作标签可能缺失时只监督可确认字段。
- [ ] **步骤 7.4**：切分独立测试。
- [ ] **步骤 7.5**：用 PyTorch 做监督基线。。

## 4. 应让 AI/Codex 实现的工作
设计 state/action 编码；先训练目标球/袋口分类器，再在有量化标注时训练连续参数回归；展示专家 Top-K 命中率、校准曲线、失误样本；导出模型权重和配置。

将任务拆成每次可运行的最小提交：先定义接口和假数据，再实现主流程，再补边界测试，最后做 UI 和性能。每次提交必须记录为什么这么做。

## 5. 需要自己掌握的原理
行为克隆、分类与回归、离线监督学习、偏差累积、协变量偏移、过拟合。

要求自己能回答：本步骤输入是什么、输出是什么、依赖的假设是什么、有哪些反例、怎么验证而不是凭感觉判断？

## 6. 验收与下一阶段入口
超越规则基线才考虑使用；对未标注杆法不强行编造监督信号；能重复训练并固定数据快照。

## 7. 常见跑偏与纠正
- 第三方库接口未知时先跑官方最小示例，不凭记忆写不存在的方法。
- 失败样例必须记录，不能只展示一条成功演示。
- 和职业水平有关的结论必须基于现实的独立数据验证。
- 复杂算法不必立即引入，先把最简单可评测的基线做出来。

## 每一步的统一完成标准（DoD）
1. 代码进入版本控制，类型检查、格式化及单元测试通过。
2. 使用固定样例运行并保存输入、输出、运行环境与耗时。
3. 至少编写一条正常、一条边界、一条异常测试。
4. README 中有运行命令、重现步骤、已知限制。
5. 未达到验收标准不得把任务标记为完成；记录失败原因、后续实验。

# 阶段 M3：仿真校准

## 1. 本阶段目标
用真实击球评估并校准仿真，识别不可观测变量。

## 2. 开始前必须具备
完成上一阶段的验收；参照总体路线与数据字典，核对输入是否真实可得；缺少授权真实数据时先使用人工合成测试数据。

## 3. 逐项执行顺序
- [ ] **步骤 4.1**：取得获准数据。
- [ ] **步骤 4.2**：优先直球再碰库/杆法。
- [ ] **步骤 4.3**：同步轨迹与口述。
- [ ] **步骤 4.4**：球杆速度/杆点不可见时做范围估计。
- [ ] **步骤 4.5**：数据集按球员/日期/桌划分训练与测试。
- [ ] **步骤 4.6**：选择损失指标。。

## 4. 应让 AI/Codex 实现的工作
实现轨迹重采样与时间对齐、停位误差、轨迹距离误差、进球一致率计算；物理参数拟合（摩擦系数、恢复系数等）；自动出 CSV/Markdown 报告和误差分布图。

将任务拆成每次可运行的最小提交：先定义接口和假数据，再实现主流程，再补边界测试，最后做 UI 和性能。每次提交必须记录为什么这么做。

## 5. 需要自己掌握的原理
什么是参数可辨识性？为什么 XY+口述不足以反推精确杆法？什么是训练/验证/测试泄漏？

要求自己能回答：本步骤输入是什么、输出是什么、依赖的假设是什么、有哪些反例、怎么验证而不是凭感觉判断？

## 6. 验收与下一阶段入口
至少有代表性样本集与独立留出集；每个样本可追溯到原始数据版本；记录校准前后性能及误差来源；没有达标不宣称高精度。

## 7. 常见跑偏与纠正
- 第三方库接口未知时先跑官方最小示例，不凭记忆写不存在的方法。
- 失败样例必须记录，不能只展示一条成功演示。
- 和职业水平有关的结论必须基于现实的独立数据验证。
- 复杂算法不必立即引入，先把最简单可评测的基线做出来。

## 每一步的统一完成标准（DoD）
1. 代码进入版本控制，类型检查、格式化及单元测试通过。
2. 使用固定样例运行并保存输入、输出、运行环境与耗时。
3. 至少编写一条正常、一条边界、一条异常测试。
4. README 中有运行命令、重现步骤、已知限制。
5. 未达到验收标准不得把任务标记为完成；记录失败原因、后续实验。

# 阶段 M2：物理仿真

## 1. 本阶段目标
建立可从初始状态与击球动作生成整段球轨迹的物理适配层。

## 2. 开始前必须具备
完成上一阶段的验收；参照总体路线与数据字典，核对输入是否真实可得；缺少授权真实数据时先使用人工合成测试数据。

## 3. 逐项执行顺序
- [ ] **步骤 3.1**：安装 Pooltool 前核查 Python 兼容性。
- [ ] **步骤 3.2**：运行官方 hello world。
- [ ] **步骤 3.3**：理解球/球、球/库、滚动/滑动、旋转和入袋。
- [ ] **步骤 3.4**：定义自家 Action(方向、速度、杆点)。
- [ ] **步骤 3.5**：将中式球桌几何映射。
- [ ] **步骤 3.6**：做逐事件轨迹输出。。

## 4. 应让 AI/Codex 实现的工作
先写 `Simulator` 抽象接口，再实现 PooltoolAdapter；做一球直线、两球碰撞、碰库、不同杆法最小实验；展示输入参数、运动轨迹与停位。

将任务拆成每次可运行的最小提交：先定义接口和假数据，再实现主流程，再补边界测试，最后做 UI 和性能。每次提交必须记录为什么这么做。

## 5. 需要自己掌握的原理
碰撞动量、滚动与滑动、杆点偏移如何导致旋转？仿真器预测与实测为何不同？

要求自己能回答：本步骤输入是什么、输出是什么、依赖的假设是什么、有哪些反例、怎么验证而不是凭感觉判断？

## 6. 验收与下一阶段入口
五类固定动作均可重复模拟；在固定随机种子和物理参数下结果一致；每次模拟打印耗时及事件。

## 7. 常见跑偏与纠正
- 第三方库接口未知时先跑官方最小示例，不凭记忆写不存在的方法。
- 失败样例必须记录，不能只展示一条成功演示。
- 和职业水平有关的结论必须基于现实的独立数据验证。
- 复杂算法不必立即引入，先把最简单可评测的基线做出来。

## 每一步的统一完成标准（DoD）
1. 代码进入版本控制，类型检查、格式化及单元测试通过。
2. 使用固定样例运行并保存输入、输出、运行环境与耗时。
3. 至少编写一条正常、一条边界、一条异常测试。
4. README 中有运行命令、重现步骤、已知限制。
5. 未达到验收标准不得把任务标记为完成；记录失败原因、后续实验。

# 测试体系与发布关卡

## 一、固定测试套件
- 数据质量：正常数据、时间戳乱序、球重叠、丢球、漂移、重复轨迹。
- 规则：合法球、黑八过早、白球入袋、轮次变化、防守、不同规则版本。
- 物理：直线球、切球、碰库、多球碰撞、旋转、多种桌参数。
- 策略：进球最容易 vs 下一杆走位最好、防守占优、长台低概率球。
- 流式：乱序消息、重复帧、取消旧计划、前端断线、任务超时、多人同时请求。

## 二、统一测量指标
| 指标 | 采样/解释 |
|---|---|
| 停位误差（米） | 真实与模拟白球终点欧氏距离，中位数/p90 |
| 轨迹误差 | 时间对齐后的平均距离，另列轨迹缺失率 |
| 进球判定准确率 | 在留出集上的准确率/混淆矩阵 |
| 推荐合法率 | 首先必须达到 100% 的已覆盖规则场景 |
| 单杆进球成功率 | 按真实球员能力及球型分层测量 |
| 清台成功率 | 固定初态多次尝试，记录 95% 置信区间 |
| 单杆端到端延迟 | 前端稳定球局提交到前端可显示推荐 p50/p95/p99 |
| 路线衔接成功率 | 无旧版本混入，动画顺序正确，缓冲等待可见 |

## 三、职业级水平的判定
需要与职业球员在**同样初始球局**、固定能力档位下做重复实验，比较进球成功率、清台率、犯规率、主观可执行性和真实操作者表现。不设未经实测的“职业级”自动通过阈值；由团队制定统计功效和业务门槛。

## 四、发布门槛
- 安全规则不能生成明显违规的击球建议。
- 算法发布时保存数据集/规则集/物理参数/模型版本和测评报告。
- 延迟目标未达标时返回降级方案（只给合法简单建议、稍后完善清台），绝不假称达标。
- 前端展示预测和真实的区别，用户实际击球后重算。

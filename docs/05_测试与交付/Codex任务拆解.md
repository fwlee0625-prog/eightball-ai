# Codex 任务卡：按顺序复制，每次一张卡

## 工作原则
AI 可以写代码，但你必须能说明本次输入、输出、假设、验收、失败条件。每张任务卡先让 Codex 解释改动，再写代码，最后让其运行测试。

### 卡片 01：准备与初始化
**目标：** 建立一个能运行、能测试、能复现的研发工程。
**发给 Codex：** “阅读 README 和 `02_阶段实施/00_准备与初始化.md`。先提议 3～6 个小提交，仅执行第一个；每个提交先写测试，再实现；列出使用到的第三方 API 官方来源，给出本地验证命令和失败时回滚方案。”
**我必须检查：** 本地 Vue 与 API 均启动，/health 200，CI 绿灯，错误配置有可理解报错。

### 卡片 02：球局建模和回放
**目标：** 把 200FPS 的球坐标与职业球员讲解转成干净、可分析的数据。
**发给 Codex：** “阅读 README 和 `02_阶段实施/01_球局建模和回放.md`。先提议 3～6 个小提交，仅执行第一个；每个提交先写测试，再实现；列出使用到的第三方 API 官方来源，给出本地验证命令和失败时回滚方案。”
**我必须检查：** 能够导入一局样例，按时间顺序回放；发现超界、重叠、丢球、时间不连续；不需要真实隐私数据可用人工样例。

### 卡片 03：物理仿真
**目标：** 建立可从初始状态与击球动作生成整段球轨迹的物理适配层。
**发给 Codex：** “阅读 README 和 `02_阶段实施/02_物理仿真.md`。先提议 3～6 个小提交，仅执行第一个；每个提交先写测试，再实现；列出使用到的第三方 API 官方来源，给出本地验证命令和失败时回滚方案。”
**我必须检查：** 五类固定动作均可重复模拟；在固定随机种子和物理参数下结果一致；每次模拟打印耗时及事件。

### 卡片 04：仿真校准
**目标：** 用真实击球评估并校准仿真，识别不可观测变量。
**发给 Codex：** “阅读 README 和 `02_阶段实施/03_仿真校准.md`。先提议 3～6 个小提交，仅执行第一个；每个提交先写测试，再实现；列出使用到的第三方 API 官方来源，给出本地验证命令和失败时回滚方案。”
**我必须检查：** 至少有代表性样本集与独立留出集；每个样本可追溯到原始数据版本；记录校准前后性能及误差来源；没有达标不宣称高精度。

### 卡片 05：下一杆推荐
**目标：** 从合法球局推荐真人容易执行的目标球、方向、力度与杆法。
**发给 Codex：** “阅读 README 和 `02_阶段实施/04_下一杆推荐.md`。先提议 3～6 个小提交，仅执行第一个；每个提交先写测试，再实现；列出使用到的第三方 API 官方来源，给出本地验证命令和失败时回滚方案。”
**我必须检查：** 固定球局能输出合法建议，模型参数变动可解释；有防守候选；p50/p95 单杆服务耗时记录；真人难打的长球须受惩罚。

### 卡片 06：清台规划与流式播放

**目标：** 在可校准仿真环境里自我提升并与传统搜索融合。
**发给 Codex：** “阅读 README 和 `02_阶段实施/07_强化学习与融合.md`。先提议 3～6 个小提交，仅执行第一个；每个提交先写测试，再实现；列出使用到的第三方 API 官方来源，给出本地验证命令和失败时回滚方案。”

**目标：** 保证用户体验、可靠性与真实球桌效果。

## 常见追问模板
- “你为什么要这样设计而不是直接写一个函数？”
- “给我两种会使方案失败的球局例子，并添加测试。”
- “刚才的 API 是否来自当前版本官方文档？给出 URL 和已验证命令。”
- “对比没有这个算法的基线，新增方案究竟提升多少？”
- “如何回滚模型、物理参数或规则版本？”

# 总览：从零到职业级可执行清台建议

## 一、用户看到的完整闭环
摄像头检测球局静止 → 视觉系统提供球桌标定和全部球 XY 坐标 → 规则校验 → <1s 级目标的下一杆推荐 → 大屏渲染瞄准线、力度、杆法、白球停位 → 规划器持续追加后续杆动画 → 用户实际击球 → 新局面触发版本切换、丢弃旧路线并重算。

## 二、核心技术结论
- 几何算法：优先发现合法、可碰到目标球的击球候选。
- 物理仿真：预测出杆到静止的轨迹、撞击与停位。
- 鲁棒优化：对方向、速度、杆点加入误差分布，选择真人更容易成功的方案。
- 多杆搜索：把白球走位、后续可打性和防守纳入路线评价。
- 深度学习（模仿学习）：用专家示范作为候选生成器/策略初值，而非唯一真理。
- 强化学习：仿真中自我练习，经现实数据校验后再使用。
- 最终采用**规则 + 仿真 + 搜索 + 学习模型**混合决策，可以按评测逐项替换。

## 三、项目里程碑与进入条件
| 关卡 | 交付品 | 依赖 | 可否独立演示 |
|---|---|---|---|
| M0 | 单仓库、前后端启动、CI | 无 | 是 |
| M1 | 手工摆球、JSON 导入、200FPS 轨迹回放 | M0 | 是 |
| M2 | 单杆仿真与参数面板 | M1 | 是 |
| M3 | 轨迹对比与误差报告 | M2 + 授权的真实数据 | 是 |
| M4 | 合法下一杆推荐、方向力度杆法 | M2、规则；建议 M3 | 是 |
| M5 | 两至三杆搜索、分段动画 | M4 | 是 |
| M6 | 模仿学习实验与固定测试集 | M1、可用专家标签 | 是 |
| M7 | RL 训练环境与策略融合 | M2/M3/M6 | 是 |
| M8 | 性能优化、真实球桌验证与版本发布 | M4/M5/M7 | 是 |

## 四、工作顺序
主线：M0 → M1 → M2 → M3 → M4 → M5 → M8。
并行研究：M1 后可整理专家标签；M2 稳定之后可以独立开展 M6；RL 必须等待环境可靠，不应为了赶进度跳过校准。
时间不承诺固定天数：单人工作量、数据质量、设备和仿真误差均未知。每个里程碑以验收通过为准。

## 五、个人学习策略
每个任务遵循：问题定义 → 最小实验 → Codex 写代码 → 自己解释输入/输出、为什么这样做 → 用真实数据做反例 → 固化测试。
重点理解数据坐标系、几何瞄准、接触与旋转、统计成功率、搜索、过拟合、可复现训练，而不是一开始阅读全部论文。

## 六、禁止的捷径
- 不把球员口述的“五成力”当作不同球员通用的米/秒。
- 不用训练集上的表现声称职业级。
- 不用模拟命中率直接替代真人命中率。
- 不在真实用户击球后继续播放旧球局路线。
- 不让大型 CPU 仿真阻塞 WebSocket 事件循环。
- 不把一次确定性规划称为必然清台。

CSV 契约与边界验证：
1. 使用 `data/samples/trajectory-001.csv` 导入，预期得到 6 帧、源帧索引 `0, 50, 100, 200, 250, 350`，时间戳为 `0, 250000000, 500000000, 1000000000, 1250000000, 1750000000` ns，每帧保留 16 个检测目标。
2. 确认 CSV 每行表示一个检测目标；元数据按行重复且必须一致；列顺序可变；UTF-8 BOM、CRLF、双引号转义和被引号包裹的逗号 / 换行可正确读取。缺省或空 `confidence` 应保持缺失，不得自动填值。
3. 确认 `frame_index` 和 `timestamp_ns` 由原始记录决定；缺帧保持为索引 / 时间戳间隔，不按 nominal FPS 补帧。首帧必须为索引 0、时间戳 0；同一帧的所有检测必须共享同一时间戳。
4. 使用临时 CSV 副本分别制造缺少必需列、重复列、未知列、列数不符、错误 schema 版本、元数据不一致、同帧时间戳不一致、重复检测 ID、非法数字和超出台面边界的坐标。每种输入都必须明确拒绝；失败不能覆盖已加载轨迹或当前球局。
5. 确认不带 `confidence` 列的 CSV 仍可导入；超过 1 MiB 的文件被拒绝；非 `.csv` / `.json` 扩展名被拒绝；既有 JSON 导入仍可用。
6. 在本地通过 Spark 管理已有 web 服务，访问 localhost，避免重复启动已经运行的服务。PC 窗口检查 1280×720 与 1440×900：导入控件可达，右侧面板独立滚动，回放仍按真实时间戳定位；检查键盘焦点、Console 和 Network。导入过程不应上传文件或调用新 API。
7. 最后退出回放并恢复原始样例，确认 16 个目标、原始坐标与状态版本未被 CSV 导入 / 回放改写。

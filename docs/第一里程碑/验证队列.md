## 连续执行约定

1. 检查 `git status --short --branch`、`git rev-parse HEAD`、待验代码是否已包含目标提交。先阅读对应 M 的最新一段以独立 `,,,` 包围的提示词及其紧随的日志。
2. 严格依照本队列顺序，从 M1.3 开始；一个 M 的**本地范围验收 PASS** 后，向其验证日志**追加**日期、命令和实际退出码、截图或证据位置、限制及结论，并在本队列下方追加短状态条目。严禁覆盖历史 FAIL/NOT RUN。
3. 用户说“连续验证多个”时，可在一个 Codex 会话里按顺序执行多个节点。**如某项 FAIL、BLOCKED 或 NEEDS REVIEW，立即停止自动推进后续项**，向开发方报告失败与复现；不要跳过，也不要改动业务代码掩盖问题。已有 M1.4、M1.5 的 PASS 不重测，除非代码变更使其受影响或用户另行要求回归。
4. Codex 只负责验证及附带证据的文档提交，提交使用英文 Conventional Commit 前缀和中文摘要；不主动修改算法、Schema、Web 业务实现或依赖。文档提交前 `git diff --check`，检查工作区已有用户改动，不擅自暂存其文件；每个 M 独立记录，允许一次多项的日志文档提交但仍须逐项证据。
5. 远程 CI PASS 不可取代本地运行；真实球台、球径、口袋、视觉相机、GLB 外观标定、真实200FPS及职业讲解自动语义推断并未验证。**即使 M1.3～M1.9 合成范围全部 PASS，也不把第一里程碑整体标记为真实数据验收完成**；待实际数据具备后另附证据验收。

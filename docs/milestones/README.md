## 每个 M 文档的固定格式

1. 首行显示 M 编号和标题。
2. 每轮提示词前单独写明可确认的本地时间，格式为 `YYYY-MM-DD HH:mm（Asia/Shanghai）`。
3. 提示词必须由单独一行的 `,,,` 包裹。
4. **验证日志紧跟在该提示词下方**，记录实际操作、命令、退出码、结果、证据路径、失败和未决事项。
5. 同一个 M 需要多轮开发/验证时，在同一文件末尾追加新的时间、提示词和日志；不要覆盖或删除旧轮次的结果。

## 当用户说“继续验证”时，Codex 必须遵循

1. 先读根目录 `AGENTS.md`、根目录 `README.md`、`docs/AGENTS.md` 和本文件。
2. 根据“当前进度指针”打开对应的里程碑 / M 文档，阅读该 M 的全部历史记录。
3. 找到该 M **时间最新、尚未完成或仍有 NOT RUN / FAIL / BLOCKED 项的提示词**，严格按提示词执行。不要自行改成开发任务，不要跳到另一个 M，也不要重复已经完整通过的人工验收。
4. 开始前检查分支、HEAD、工作区和本地环境；保护所有已有修改。提示词要求只验证时，不要修改业务代码、依赖、锁文件或模型资产。
5. 把真实结果直接追加在对应提示词的 `### 验证日志` 下。保留旧日志；新一轮需要重试时，追加新的时间 + `,,,` 提示词 + 新日志，不覆盖失败历史。
6. 未执行的项目明确标为 `NOT RUN`；失败标为 `FAIL` 并保留原始错误；缺少条件标为 `BLOCKED`。不能根据远程 CI 或代码阅读把本地浏览器验收写成 PASS。
7. 如果当前 M 的最新提示词所有验收项均已实际通过，更新本文件的当前进度指针，并报告当前 M 已完成；不要擅自实现下一个 M。
8. 新的验证日志只写在对应 M 文档中。旧文件 `docs/verification/LOCAL_VALIDATION_LOG.md` 是历史归档，不再追加新的常规验证记录。

## 状态定义

- `NOT RUN`：尚未实际执行。
- `PASS`：已实际执行，满足明确的验收标准并保留证据。
- `FAIL`：已执行但未满足验收标准。
- `BLOCKED`：因工具、依赖、权限或环境缺失无法执行。
- `NEEDS REVIEW`：需要用户确认真实几何、坐标语义或业务假设。

远程 CI、自动化测试、PC 浏览器人工验收是不同证据，必须分别记录，不得互相替代。

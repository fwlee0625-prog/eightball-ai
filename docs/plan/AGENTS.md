# 研发规划文档要求

本规则适用于 docs/plan，并继承根目录 AGENTS.md 与 docs/AGENTS.md。

- 本目录记录目标架构、技术研究、阶段计划和验收门槛，不是运行时代码。
- 不因为某项计划写得详细就标记为已实现；状态变更必须有代码路径、测试结果或实验记录支持。
- 保持阶段编号和依赖顺序稳定；调整里程碑时说明原因、前置条件和验收变化。
- 接口草案必须注明“设计草案 / 尚未实现”，正式契约以 packages/contracts 中实际提交的版本为准。
- 第三方 API、安装方式、版本兼容和规则文本应以当前官方来源核对，并记录 URL、日期和环境限制。
- 对“1 秒”“职业级”“高成功率”等目标定义测量起止、数据集、基线和统计方法；没有实测数据时只能写成目标。
- 新增任务需包含目标、前置条件、最小实现、测试、验收标准、常见失败和回滚 / 降级方式。
- 保留 XY 观测无法唯一推断旋转、杆点或精确速度等可观测性限制，不得在后续文档中无依据地消除这些限制。

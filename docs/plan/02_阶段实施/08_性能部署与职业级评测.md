# 阶段 M8：性能部署与职业级评测

## 1. 本阶段目标
保证用户体验、可靠性与真实球桌效果。

## 2. 开始前必须具备
完成上一阶段的验收；参照总体路线与数据字典，核对输入是否真实可得；缺少授权真实数据时先使用人工合成测试数据。

## 3. 逐项执行顺序
- [ ] **步骤 9.1**：确认“一秒”测量起止。
- [ ] **步骤 9.2**：分预算：入参校验、候选初筛、仿真、评分、传输及渲染。
- [ ] **步骤 9.3**：缓存、批处理、进程隔离、并发限流。
- [ ] **步骤 9.4**：真实球员对照测试与分级能力档案。
- [ ] **步骤 9.5**：持续监控。。

## 4. 应让 AI/Codex 实现的工作
实现 OpenTelemetry 或结构化 trace、p50/p95/p99 指标、超时回退、模型发布开关、回滚、线上灰度与评测基准；构建真实球桌测试记录。

将任务拆成每次可运行的最小提交：先定义接口和假数据，再实现主流程，再补边界测试，最后做 UI 和性能。每次提交必须记录为什么这么做。

## 5. 需要自己掌握的原理
延迟分位数、计算预算、故障隔离、模拟成功率与现实成功率区别、A/B 测试。

要求自己能回答：本步骤输入是什么、输出是什么、依赖的假设是什么、有哪些反例、怎么验证而不是凭感觉判断？

## 6. 验收与下一阶段入口
目标硬件上下一杆端到端 p95≤1s（如果无法达到，明确记录并降级）；非法推荐 0 容忍；真人成功率、清台率和专家主观评价有统计置信区间。

## 7. 常见跑偏与纠正
- 第三方库接口未知时先跑官方最小示例，不凭记忆写不存在的方法。
- 失败样例必须记录，不能只展示一条成功演示。
- 和职业水平有关的结论必须基于现实的独立数据验证。
- 复杂算法不必立即引入，先把最简单可评测的基线做出来。

## 每一步的统一完成标准（DoD）
1. 代码进入版本控制，类型检查、格式化及单元测试通过。
2. 使用固定样例运行并保存输入、输出、运行环境与耗时。
3. 至少编写一条正常、一条边界、一条异常测试。
4. README 中有运行命令、重现步骤、已知限制。
5. 未达到验收标准不得把任务标记为完成；记录失败原因、后续实验。

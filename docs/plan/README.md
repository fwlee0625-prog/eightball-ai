# 中式八球 AI 决策与清台规划系统：研发实施与原理学习手册 V1.0

- 编写日期：2026-10-27
- 适用对象：有 Vue / Node 开发基础、准备使用 Python 研发台球决策系统的开发者
- 阅读方式：先读 00_总览/路线总图.md，然后按 02_阶段实施 的编号执行。
- 本目录是详细的研发规划文档，不是已经写好的可运行成品，也不是经过真实球桌验收的模型。
- 核心目标：中式八球静止球局输入 → 约 1 秒内给出下一杆推荐 → 分段生成清台规划和动画；依据每次真实击球后的新状态重算。
- 成功标准：更容易被人执行的高成功率方案；允许优于专家示范，不追求机械地复制职业打法。

## 当前仓库实现边界

截至当前 main 分支，已完成两项基础工作：

1. packages/contracts 中的视觉输入与标准球局 JSON Schema、python/billiards_core 中的坐标校验 / 状态转换，以及一组固定样例和单元测试。
2. apps/web 第一版三维球局工作台：加载用户提供的 billiards.glb、渲染 16 个视觉检测目标、提供视角切换、目标选择和本地坐标编辑。

apps/api、完整赛事规则、物理仿真、候选评分与搜索、python/billiards_ml、scripts 和跨模块集成测试仍未实现。前端模型拟合与台面表面高度仍是临时估计；本地坐标编辑不写回样例或后端。M0 计划中的 FastAPI /health、CI 等验收项目前尚未在仓库中看到对应实现。只有在功能已实现、相关测试实际运行并留下验收证据后，才能将其标记为完成。

当前开发分支在 main 的基础上还已实现 FastAPI `/health` 与前端健康状态、轨迹 Schema v0.1.0 / TypeScript 与 Python 校验器、合成轨迹 JSON 和时间戳驱动的 2D / 3D 回放；R-015 已记录该回放的本地 PC 浏览器验收。当前分支新增 CSV 导入与 `data/samples/trajectory-001.csv`，远程自动化 CI 已通过，本地验收尚待执行；CSV 导入不等于真实 200 FPS 数据接入，数据质量报告及球桌几何标定仍未完成。

本文档里的历史接口、目录、指标和技术方案仍需按实际代码理解；已提交的正式初版契约以 packages/contracts/schemas 中的 Schema 为准。

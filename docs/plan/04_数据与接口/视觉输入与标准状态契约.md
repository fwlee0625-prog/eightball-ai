# 视觉输入与标准状态契约（首版）

## 状态

已实现首版结构 Schema、Python 坐标校验 / 状态转换函数和固定样例。版本为 0.1.0；本文件只描述第一步的输入边界，不代表规则、物理仿真或决策功能已经实现。

## 输入与输出

- 原始视觉样例：data/samples/vision-balls-001.json
- 原始输入 Schema：packages/contracts/schemas/vision-balls.schema.json
- 标准状态样例：data/samples/table-state-001.json
- 标准状态 Schema：packages/contracts/schemas/table-state.schema.json
- 转换实现：python/billiards_core/billiards_core/state.py

视觉原始数组保留 id、x、y，可选 confidence。转换函数补充 table_id、state_version、source、坐标系与台面几何元数据，并把 x / y 改为明确带单位的 x_mm / y_mm。

## 第一版台面与坐标假设

- 活动台面长度：2540 mm。
- 活动台面宽度：1270 mm。
- 暂定原点：活动台面中心。
- X 轴：沿台面宽度方向。
- Y 轴：沿台面长度方向。
- 正方向：目前沿用视觉提供方的定义，尚未通过标定确认；输出标记为 provisional。
- 台面矩形范围：X 在 [-635, 635] mm，Y 在 [-1270, 1270] mm。

这些是用于启动开发的显式假设。当前转换不会自动旋转、镜像或缩放坐标；如果视觉坐标实际采用不同的原点、轴向或单位，必须先增加并验证坐标变换，不能直接把当前结果用于物理仿真。

## ID、半径和边界约束

- id 仅作为视觉来源提供的标识，当前不假定 id=0 是白球，也不假定 id 直接代表花色或球的规则身份。
- 球半径尚未确认，所以首版只校验点是否落在活动台面矩形内。
- 首版不检查球体重叠，不推断袋口中心或轮廓，也不判定球是否静止。
- confidence 是可选字段；若提供，必须是 [0, 1] 范围内的有限数值。
- 单帧内 id 必须唯一，范围为 0 到 15；允许视觉只检测到部分球，但至少需要一个检测结果。
- 坐标必须是有限数值，超出活动台面矩形的点会被拒绝。

## 转换示例与验证

从仓库根目录运行：

    PYTHONPATH=python/billiards_core python -m unittest discover -s python/billiards_core/tests -v

转换函数按 ID 排序输出，以获得稳定、可复现的标准 JSON。测试覆盖样例转换、重复 ID、越界、NaN / Infinity、错误类型、置信度和输入不可变性。

## 当前前端状态

apps/web 已提供第一版三维工作台：从标准状态样例渲染球桌和 16 个检测目标，可选中目标、检查并编辑坐标。编辑仅存在于浏览器会话中，不会改写原始样例或调用后端。GLB 的包围盒拟合与台面表面高度是临时估计，不可直接用于物理仿真。

## 下一步

2. 确认球半径和六个袋口的几何定义，再实现球体可达区域与碰撞校验。
3. 确认 id 是逐帧检测编号、跨帧跟踪 ID，还是实际球号；规则语义应单独建模。
4. 为观测增加 frame_id、captured_at_ns 和置信度，随后定义多帧轨迹契约。

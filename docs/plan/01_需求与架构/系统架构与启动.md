# 软件架构、模块解耦和启动

## 推荐：一个 Monorepo + 模块化单体 + 离线训练
```text
billiards-ai/
  apps/web/                  # Vue 3 + TS + Vite 球桌回放与教练界面
  apps/api/                  # FastAPI HTTP + WebSocket 入口
  packages/contracts/        # JSON Schema/OpenAPI 契约及版本
  python/billiards_core/     # 规则、几何、状态、评分、仿真适配、搜索
  python/billiards_ml/       # 数据集、模型、训练、策略适配
  scripts/                   # 数据转换、离线校准与评测
  tests/                     # 单元、集成、固定球局基准
  data/samples/              # 仅脱敏、授权样例
  docs/                      # 项目文档
```

## 进程和通信
开发时：**前端一个进程 + FastAPI 一个进程**。核心 Python 模块为普通包，仿真、规则和决策函数直接调用，不互相发送 HTTP。模型训练按需用独立命令/进程，不在线上请求路径中运行。

- 浏览器 → FastAPI：HTTP 提交球局、请求下一杆；WebSocket 订阅逐段规划。
- FastAPI → core：同步函数/线程池或进程池中的函数调用。CPU 密集型要使用**独立工作进程/进程池**并限流，不是把 `async def` 换写法即可。
- FastAPI → ML：加载已冻结的模型权重进行推理；训练单独执行。
- 后期在并发增长、超时无法控制时，拆出独立规划 worker 和可靠消息队列；不要一开始就六个服务。

## 代码边界
`RuleEngine.validate(state, action)`、`Simulator.simulate(state, action, params)`、`CandidateGenerator.generate(state)`、`Evaluator.score(state, action, outcomes, player_profile)`、`Planner.plan(state, budget)`、`Policy.propose(state)`。这是**自定义设计接口**，不是 Pooltool 已有 API。

## 本地启动（计划中的脚手架命令，须在 M0 实现）
```bash
# 终端 1：Vue
cd apps/web && npm install && npm run dev
# 终端 2：FastAPI，先建立虚拟环境并安装依赖
cd apps/api && uvicorn main:app --reload
# 训练：只在阶段 M6/M7 单独运行脚本（命令由脚本实现后确定）
```
不得把这些命令理解为压缩包已经包含可运行代码。

## 版本边界
每次规划与 `table_id / shot_id / state_version / ruleset_version / physics_version / model_version` 绑定；旧消息前端丢弃。

# 文档编写要求

本规则适用于 docs，并继承根目录 AGENTS.md。

- 面向本项目的主要读者使用中文说明；代码标识符、路径和官方 API 名称保持原文。
- 明确区分规划中、已实现、已验证和已发布，不能用未来时目标描述当前功能。
- 记录假设、限制、依赖、输入 / 输出、失败路径、验证方式和相关文档链接。
- 内部链接使用相对路径，修改或移动文件后检查链接目标。
- 外部技术信息尽量引用官方文档；写明核对日期和版本范围，避免把单次浏览结果当成永久事实。
- 规则、Schema、坐标系、单位、事件字段和验收指标必须与代码及测试保持一致。
- 不承诺未经测量的性能、清台率或职业水平。
- 文档变更后检查 README 导航、目录名、命令和示例是否与当前仓库一致。


## 里程碑验证提示词与日志规范

- 验证提示词与每轮真实结果以 `docs/milestones/` 为准；先读 `docs/milestones/README.md` 确认当前里程碑 / M 和最新待验证轮次。
- 每个 M 文件按时间顺序追加轮次。每轮写标题、可确认的本地时间、独立一行 `,,,`、完整提示词、结束的 `,,,`，然后紧跟 `### 验证日志`。
- 验证日志必须包含真实执行环境、命令或手动操作、退出码 / 实际结果、证据路径、失败和未决事项。未执行项写 `NOT RUN`；远程 CI 不替代本地浏览器验收。
- 不覆盖历史提示词或日志。重试时追加新的时间戳轮次；只更新索引中的当前进度指针。
- `docs/verification/LOCAL_VALIDATION_LOG.md` 是历史归档，不再追加常规新轮次。

# Web 前端开发要求

本规则适用于 apps/web 下的全部文件，并继承根目录 AGENTS.md。

## 开发前

先阅读本目录 README.md、根目录 README.md，以及 docs/plan 中与当前功能相关的架构、数据字典和流式消息草案。检查现有组件和测试后再决定如何扩展。

## 技术约束

- 使用 Vue 3、TypeScript、Composition API 和 script setup；避免无必要的 Options API 混用。
- 使用现有 Pinia、Vue Router、Vite、Vitest 配置，不擅自引入第二套状态管理或路由方案。
- 依赖版本以 package.json、pnpm 配置和后续锁文件为准。变更依赖前核验官方文档与实际安装版本。
- 不在 App.vue 中堆放所有页面逻辑；随着真实功能出现再按职责拆分组件、页面、composables 和 services。
- UI 不实现球体碰撞、赛事规则、候选评分、搜索或模型推理；这些逻辑属于后端领域模块。

## 数据与接口

- 跨模块类型优先引用 packages/contracts 中的已实现契约；在该模块尚未实现前，避免创建多个相互冲突的临时 DTO。
- 不假设后端 API 已存在。对尚未实现的接口使用明确标注的 mock / fixture，并确保 UI 不把模拟响应伪装成真实 AI 结果。
- 球桌坐标、单位、规则版本和状态版本必须显式处理。
- 预测轨迹与真实观测使用不同的视觉表达；新真实状态到达后立即废弃旧版本规划。
- WebSocket 事件要考虑重复、乱序、断线、取消、版本不匹配和任务失败。

## 测试与质量

- 使用 Vitest 和 Vue Test Utils 验证组件行为。
- 至少覆盖正常路径、空状态 / 边界输入和错误路径。
- 重要交互考虑键盘可达性、焦点、文本提示和不同屏幕宽度。
- pnpm lint 会自动修复文件；只检查时使用 pnpm exec oxlint . 与 pnpm exec eslint .。
- 修改后运行相关测试和类型检查；若未运行，必须在汇报中说明。

## 不要做

- 不要保留脚手架 counter 示例作为业务状态设计。
- 不要硬编码未来 API 的成功响应或声称已实现规划能力。
- 不要在前端保存密钥、未授权视频或原始个人数据。
- 不要把预测成功率或规划路线显示成确定性保证。

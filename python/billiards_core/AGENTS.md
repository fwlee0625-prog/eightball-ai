# Billiards Core 开发要求

本规则适用于 python/billiards_core，并继承根目录 AGENTS.md。

## 领域边界

- 本模块负责规则、几何、仿真适配、候选生成、评分与搜索。
- 不导入 Vue、FastAPI 路由或 WebSocket 传输代码。
- 不在核心包里执行模型训练；学习策略通过清晰的候选 / 策略接口接入。
- 赛事规则必须按明确的中式八球规则版本配置，不能默认等同于美式八球。
- 视觉 ID 只作为来源标识；在确认前不得把某个 ID 假定为白球、花色球或标准球号。

## 数值与可复现性

- 坐标、速度、角度、时间和球半径必须显式注明单位。
- 当前第一版视觉输入暂按 mm、台面中心原点、X 沿宽度、Y 沿长度；正方向沿用视觉来源并标记 provisional，不能假称已完成坐标标定。
- 当前台面活动尺寸为长 2540 mm、宽 1270 mm；球半径未确认前只校验台面矩形边界，不要擅自收缩边界。
- 避免依赖可变全局状态；将球桌参数、物理参数、规则版本和随机种子作为显式输入。
- 对几何边界使用有依据的容差，并用反例测试边界球、遮挡球、袋口附近和球体重叠。
- 仿真器 API 必须按当前官方文档和实际安装版本验证；先运行最小官方示例，再封装 Adapter。不得凭记忆猜 Pooltool 类名或参数。
- 物理仿真和搜索必须接受预算或截止时间，并返回可解释的超时 / 无解状态。

## 决策质量

- 先过滤规则非法动作，再对候选进行物理预测与评分。
- 评分应区分进球概率、白球走位、后续可打性、执行难度、犯规风险和防守价值。
- 输出候选、假设、预测置信度和失败原因；不得把预测说成必然结果。
- 新真实球局状态必须使旧状态的规划结果失效。

## 测试

为规则、几何、仿真适配、候选生成和规划分别编写测试。覆盖正常、边界和无效输入；使用固定合成样例和固定随机种子。任何性能优化都需与原始基线比较并报告误差变化。

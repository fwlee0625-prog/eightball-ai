# Sample Data（样例数据）

## 当前状态

已提交第一份由项目对话提供的视觉球坐标样例，以及对应的标准球局状态样例。数据仅用于开发输入契约和校验器，不代表已确认球号语义或已完成视觉标定。

## 样例文件

- vision-balls-001.json：保留视觉提供的原始 id、x、y 数值，不改变原始顺序。
- table-state-001.json：将同一批坐标映射到初版标准状态，按 ID 排序并附上暂定台面参数和坐标系元数据。
- trajectory-001.json：完全合成的逐杆轨迹，包含 6 帧、原始帧索引跳号和非等间隔时间戳，用于回放与校验器回归。

## 当前样例的解释

- 活动台面按长 2540 mm、宽 1270 mm 记录。
- 暂按台面中心为原点，X 沿宽度、Y 沿长度；正方向仍继承视觉来源，尚待标定确认。
- id 仅作为视觉来源提供的标识，不假定 id=0 是白球。
- 不包含图像、视频、球半径、袋口几何、规则状态或置信度数据。

## 数据安全要求

- 只提交人工合成数据，或明确提供给本项目使用且不存在已知使用限制的数据。
- 不提交未授权比赛视频、音频、球员个人信息、访问令牌、私人链接或其他敏感数据。
- 每份样例都应记录来源、用途、Schema 版本和必要的许可 / 脱敏状态。
- 样例用于开发与回归，不应被误认为具有统计代表性的训练集或职业水平基准。

## 合成轨迹样例

- Schema：`packages/contracts/schemas/trajectory.schema.json` v0.1.0。
- 用途：验证按实际时间戳回放、帧索引缺口、轨迹 ID 与活动台面边界；不是训练数据、真实比赛记录或物理仿真结果。
- 时间：`timestamp_ns` 从击球开始计时，单位纳秒；`nominal_fps=200` 只是来源名义帧率，帧索引 `0,1,2,4,5,7` 和实际时间戳分别保留，不能按固定 200 FPS 补齐缺帧。
- 位置：只有 ID 0 与 ID 3 在样例中随时间变化，其余 ID 保持静止以便观察；ID 仍仅为合成追踪标识。
- 来源与许可：本仓库为本项目开发创建的人工合成数据，无真实球员、视频或个人信息；可用于公开代码与自动化测试。
